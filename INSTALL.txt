BDDM 1.5.0 - installing on a Windows computer
=============================================

1. Install BDDM
---------------
Run BDDM-Setup.exe. It installs for your Windows account only (no
administrator password needed) into:
    %LOCALAPPDATA%\Programs\BDDM
Settings and download history are kept in %APPDATA%\BDDM, so updating
(running a newer BDDM-Setup.exe) keeps everything.

Windows may show "Windows protected your PC" because the setup file is not
signed with a paid certificate. Click "More info", then "Run anyway".

During setup you can choose:
  - Desktop shortcut
  - Start BDDM with Windows (it starts in the background, so the browser
    extension always finds it). You can change this later in BDDM >
    Settings > "Start BDDM with Windows".

The first time you download a video, BDDM downloads its video tools
(yt-dlp, ffmpeg, deno) by itself.

To remove BDDM: Windows Settings > Apps > "BDDM Download Manager" >
Uninstall (or Start menu > BDDM > Uninstall BDDM). Your downloaded files
are never deleted.


2. Add the browser extension
----------------------------
The extension sends your browser's downloads and videos to BDDM. BDDM must
be running (the extension says so if it is not).

The extension files are in the BDDM folder:
    %LOCALAPPDATA%\Programs\BDDM\extension\chromium      (Chrome, Edge, Brave, Opera, Vivaldi)
    %LOCALAPPDATA%\Programs\BDDM\extension\BDDM-firefox-signed.xpi   (Firefox)
Start menu > BDDM > "Browser extension folder" opens it.
Do not move or delete the "chromium" folder: the browser loads the
extension from there. Updating BDDM updates the files in place; after an
update, click the reload button of BDDM on the extensions page.

Google Chrome
  1. Open a new tab and go to:  chrome://extensions
  2. Turn on "Developer mode" (top right).
  3. Click "Load unpacked" and choose the folder
     %LOCALAPPDATA%\Programs\BDDM\extension\chromium
     (paste that path into the folder box and press Enter).
  4. Optional: click the puzzle icon and pin "BDDM Download Catcher".

Microsoft Edge
  1. Go to:  edge://extensions
  2. Turn on "Developer mode" (left side, at the bottom).
  3. Click "Load unpacked" and choose the same "chromium" folder.

Brave
  1. Go to:  brave://extensions
  2. Turn on "Developer mode" (top right).
  3. Click "Load unpacked" and choose the same "chromium" folder.

Opera (opera://extensions) and Vivaldi (vivaldi://extensions) work the
same way.

Why "Load unpacked"? Chrome, Edge and Brave only install packaged
extensions (.crx files) from their web stores. A .crx file from anywhere
else is blocked or switched off, so loading the folder is the way to use
an extension that is not in a store. Chrome may sometimes remind you that
a developer-mode extension is installed; that is normal.

Firefox
  Firefox only installs extensions signed by Mozilla.
  - Signed file (recommended): BDDM-firefox-signed.xpi in the extension
    folder above is signed by Mozilla and stays installed. Drag it into a
    Firefox window (or about:addons > gear > "Install Add-on From File...")
    and click "Add". It is not published on addons.mozilla.org; it is only
    signed.
  - Without the signed file: go to  about:debugging#/runtime/this-firefox ,
    click "Load Temporary Add-on..." and choose BDDM-firefox.xpi.
    Firefox removes it when Firefox is closed, so this is only for trying.
    (Firefox Developer Edition, Nightly and ESR can install the unsigned
    file permanently after setting xpinstall.signatures.required to false
    in about:config, then about:addons > gear > "Install Add-on From File".)
  - Signing a new version yourself: with free API keys from
    https://addons.mozilla.org/developers/addon/api/key/ run, in the BDDM
    source folder:
        set WEB_EXT_API_KEY=...
        set WEB_EXT_API_SECRET=...
        extension\sign-firefox.cmd
    (needs Node.js and Python). It writes a signed .xpi to
    extension\signed\. Open that file with Firefox (drag it into a Firefox
    window) to install it. Mozilla signs each version only once, so a
    changed extension needs a higher "version" in
    extension\manifests\base.json before signing.


3. What is new in 1.5.0
------------------------
This is a visual redesign of BDDM. Windows and the browser extension use
the same clean look, follow Windows light or dark theme, and keep every
existing feature (captures, HLS and movielinkbd, the on-video download
button, auto-yield, speed limits, torrents, Google Drive, and updates).

The browser extension is now 1.5.0. After you install this update:

  Chrome, Edge, Brave, Opera or Vivaldi (recommended)
    Open chrome://extensions (or edge://extensions / brave://extensions),
    find BDDM Download Catcher, and click Reload. If it is not there yet,
    turn on Developer mode and use "Load unpacked" on the folder
    %LOCALAPPDATA%\Programs\BDDM\extension\chromium

  Firefox
    Drag the new BDDM-firefox-signed.xpi onto about:addons. Mozilla signs
    each version only once, so you cannot update an older signed file in
    place.

- The main window has a sidebar, stats, and card-style download rows.
- Confirm, progress, complete, video, Drive, error, torrent, Settings
  and About windows share the same design. Starting a single file can
  show a compact progress ring and a complete (or error) window; the
  job stays in the main list. Folder downloads and rapid batches do not
  get a window per file.
- BDDM stays in the Windows notification area. Right-click the icon for
  Show BDDM, Add URL, Pause all, Settings and Quit; left-click opens a
  small popup with the same actions. Hovering the icon shows the speed
  and percent, for example "BDDM — 2.4 MB/s, 68%".
- The taskbar button of the main window shows a progress overlay while a
  download is running (including paused and error states).
- The extension popup (Chrome and Edge first; Firefox uses the same
  popup) is compact, with the video list, catch-download switches, and
  Open BDDM in the new look.

4. What was new in 1.4.19
------------------------
The browser extension was 1.4.19. After you installed that update, also
install the signed Firefox file (drag BDDM-firefox-signed.xpi onto
about:addons). You cannot update the 1.4.15 extension in place; Mozilla
signs each version only once. Chrome, Edge and other Chromium browsers
need the extension reloaded or loaded again from the extension folder.
- Sites that hide an HLS video playlist as a picture (for example
  movielinkbd) are now caught, including in Firefox. BDDM shows its
  download window automatically once for each stream. YouTube, Facebook
  and other sites that already had their own download flow are unchanged:
  no new automatic window appears there. The right-click menu "Download
  this video with BDDM" also works on a page where a stream was found.
  When it downloads the stream, BDDM sends the player's site (Origin) so
  the video server allows the request.
- A small "Download with BDDM" button appears on the corner of a playing
  or visible video on every site, including YouTube, Facebook and
  Instagram. It stays out of the site's own controls, follows the video
  you are watching or hovering in a feed, and is hidden on very short
  clips, tiny players and ads. Click it to open BDDM's compact video
  window (preview, title, quality, size when known, and Download). The
  window follows Windows light or dark theme. YouTube, Facebook and
  similar sites still do not get an automatic window; only the button
  is added there.


5. What was new in 1.4.18
------------------------
The browser extension is unchanged (still 1.4.15). You do not need to
reload or reinstall it.
- HLS (m3u8) streams are now downloaded by BDDM itself, including sites
  such as movielinkbd where the playlist has no ".m3u8" in the address.
  You pick the quality in the compact video window (highest is the
  default); the window follows Windows light or dark theme. Segments are
  fetched in parallel with retry and resume, including AES-128
  encryption, MPEG-TS and fMP4. They are joined into one MP4 with ffmpeg
  (stream copy, no re-encoding), and temporary pieces are removed.
  The global speed limiter and "Slow down downloads while I use the
  internet" apply the same way as for other downloads. Progress, pause
  and resume work like other jobs.

6. What was new in 1.4.17
------------------------
The browser extension is unchanged (still 1.4.15). You do not need to
reload or reinstall it.
- When you browse or another app uses the internet, BDDM automatically
  uses less bandwidth so the rest of the PC stays quick, then goes back
  to full speed when the other traffic stops. This applies to regular
  downloads, videos, Google Drive and torrents (download and upload).
  It is on by default; you can turn it off in Settings with "Slow down
  downloads while I use the internet". A small "Saving bandwidth" note
  appears in the window while BDDM is yielding.

7. What was new in 1.4.16
-------------------------
The browser extension is unchanged (still 1.4.15). You do not need to
reload or reinstall it.
- BDDM no longer opens a console or Windows Terminal tab when it starts
  after an update, from a shortcut, or when Windows starts. Status and
  download messages are written to a log file in the BDDM data folder
  (%APPDATA%\BDDM\bddm.log).

8. What was new in 1.4.15
-------------------------
The browser extension is now 1.4.15. Chrome, Edge and Brave keep the
same capture behaviour; reload the unpacked extension (or the new zip)
if you already have it installed.

Firefox users must install the new signed add-on (BDDM-firefox-signed.xpi
in the extension folder, or from this release). Mozilla signs each
version only once, so the previous 1.4.2.1 add-on cannot be updated in
place with this file — open the new .xpi (or drag it onto about:addons).
- In Firefox, BDDM now catches a download before Firefox's own downloader
  starts, so Firefox should not also save the file or show its own save
  prompt. If BDDM is not running, Firefox keeps the download as before.
- Files the page itself makes (blob: or data: links, including Send
  Anywhere-style transfers) stay in Firefox. BDDM does not intercept them.

13. What was new in 1.4.10
--------------------------
The browser extension is unchanged (still 1.4.2.1). You do not need to

16. What was new in 1.4.7
-------------------------
The browser extension is unchanged (still 1.4.2.1). You do not need to
reload or reinstall it.
- You can cap how fast BDDM downloads, for regular files and for
  torrents, and how fast torrents upload (seed). The limits are in
  Settings. A change applies at once to downloads that are already
  running, and is remembered when BDDM starts again.
- On one download you can set a different limit that overrides the
  Settings cap. Open it from the Speed limit button on that row.
  Off returns the download to the Settings cap.

18. What was new in 1.4.5
-------------------------
The browser extension is unchanged (still 1.4.2.1). You do not need to
reload or reinstall it.
- Paste a magnet link into the main window, or use "Add torrent file",
  to download a torrent into your usual BDDM folder. After it finishes
  it keeps seeding for as long as BDDM is running (including in the
  tray). There is no automatic stop by share ratio or time. Torrents
  are saved and continue downloading or seeding when BDDM starts again.
- The list shows progress, size, peers, download and upload speed, and
  the status (Downloading, Paused, Seeding, Error). Pause, resume and
  remove work; remove asks whether to also delete the files.
- The first time a torrent starts, Windows may ask to allow BDDM
  through the firewall so other peers can connect.

21. What was new in 1.4.2
-------------------------
Update the browser extension too (click its reload button on the
extensions page, or install the new BDDM-firefox-signed.xpi in Firefox).
The extension's own version number is 1.4.2.1 (Mozilla signs each number
only once).
- Streaming sites whose player runs in a frame from another site (for
  example anikoto -> megaplay.buzz): BDDM sends the same Referer as the
  browser (often only the player's site, e.g. "https://megaplay.buzz/").
  If the video server still answers 403, BDDM tries the player's full
  address and the tab's page, and remembers for that video server which
  one worked.
- Streams whose pieces are hidden behind a small picture (a fake PNG in
  front of the video data) are downloaded and made into a normal MP4 (or
  MP3/M4A); ffmpeg is told to read the pieces as MPEG-TS.
- The quality list (1080p, 720p, ...) comes from the stream's master
  playlist, with size guesses; when only one quality's playlist was found,
  BDDM uses the master playlist next to it.
- movielinkbd.tv and similar sites: playlists without ".m3u8" in the
  address that are sent as a picture (image/jpeg) are now found by their
  content. The extension reads them from the player's own frame, so the
  request has the player's Origin and Referer, and BDDM sends them too. A
  "#EXT-X-ERROR:forbidden" answer counts as a refusal (other Referers
  are tried).
- Clean file names: when a link has no useful name ("stream.mp4",
  "video.mp4", "download", a long random id), the file is named after the
  page title, without the site name or "Watch ... online", and without
  characters Windows does not allow.
- Send Anywhere (send-anywhere.com, sendanywhe.re): its download links
  work only once, so the extension leaves these downloads to the browser.
  If such a link still reaches BDDM, it is asked for exactly once (no size
  check first, one connection); a Send Anywhere page link gets a plain
  explanation.


22. What was new in 1.4.1
-------------------------
Fewer "HTTP 403 Forbidden" errors on sites where the browser itself can
download (update the browser extension too: click its reload button on the
extensions page, or install the new BDDM-firefox-signed.xpi in Firefox):
- BDDM now asks the website exactly like your browser does: the same
  browser name (User-Agent), languages, page address (Referer), Origin
  and the special headers a site's video player sends. These headers are
  kept in memory only and are never sent to mirror links.
- Cookies are sent to every server involved, also when a link moves on to
  another server (a CDN), and Chrome's per-site cookies are included.
- Video and audio files found on a page (.mp4, .webm, .mp3 ...) are
  downloaded by BDDM's fast engine instead of the video tools.
- Video streams get the same browser details and cookies (through a
  temporary cookie file that is deleted right after).
- Fewer extra requests before a download starts, so links that work only
  once or a few times are not used up.
- When a site still refuses, BDDM says so plainly and explains what to do.


23. What was new in 1.4.0
-------------------------
- Internet drops: downloads wait ("No internet connection. BDDM
  continues automatically when the connection is back") and continue by
  themselves when the internet comes back. This works for normal files and for videos (YouTube and other
  streams continue from the pieces already downloaded).
- Unfinished downloads continue when BDDM starts again (after closing it,
  a crash or a power cut). Settings > "Continue unfinished downloads when
  BDDM starts" turns this off.
- Checksums: when the server gives a checksum, or you enter one (MD5,
  SHA-1, SHA-256 or SHA-512) under "Options" or "More options" in the
  "Download File Info" window, BDDM checks the finished file. If a piece
  is damaged, only that piece is downloaded again. Finished downloads show
  "checked" when the file was verified.
- Mirror links: under "Options" you can add other links to the same file
  (one per line). BDDM downloads parts from all of them at once and stops
  using a link that does not work.
- Slow connections: if one connection is much slower than the others,
  BDDM closes it and opens a new one.
- If a server name has several addresses and one does not answer, BDDM
  tries the others; if your DNS fails, BDDM asks public DNS servers.
- Queue: Settings > "Downloads at the same time" sets how many run at
  once; the rest wait in the queue and start by themselves. Use
  "Start next", up and down to change the order.
- Errors are explained in plain words, with what to do about them.


24. What was new in 1.3.0
-------------------------
- Folders by file type: Settings > "Folders by file type" sets a folder
  for Video, Audio, Documents, Compressed, Programs, Images and Other.
  When you choose another folder in the "Download File Info" window, BDDM
  remembers it for that type of file.
- Expired download links: if a site's link expires during a download,
  BDDM says so; click the download again on the website and BDDM
  continues where it stopped (Google Drive links are renewed by BDDM
  itself).
- If the file on the server changes during a download (new version),
  BDDM starts it again instead of making a broken file.
- Servers that allow only a few connections: BDDM uses fewer connections
  for that server and remembers it for a while.
- Not enough disk space: BDDM checks before it starts and tells you how
  much space is needed.
- Safer after a power cut: download progress is saved safely every few
  seconds.
- Save as PDF for view-only Google Drive files now also works in Chrome,
  Edge and Brave.


16. Running from the source code (developers)
--------------------------------------------
Install Go (the version in go.mod or newer), unzip BDDM-src.zip and run, in that folder:
    go run .
Build the Windows program and the setup file:
    go build -trimpath -ldflags "-H windowsgui -s -w" -o build\BDDM.exe .
    python extension\build.py
    makensis installer\BDDM.nsi        (NSIS 3, https://nsis.sourceforge.io)
